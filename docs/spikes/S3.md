# Spike S3: LDPC speed

Status: done on one machine (2026-11-13). Not run on any CI runner (no runners available).

## 1. Summary

| Measure | Threshold | Measured, one core | Verdict |
| --- | --- | --- | --- |
| Layered normalised min-sum, `normal` code, exactly 10 iterations, scalar Go | 20 Mbit/s of sent bits | **7.6 Mbit/s** (median of 8; 7.4-8.3) | **Not met** |
| Same, 8 / 6 iterations, scalar | | 10.4 / 13.5 Mbit/s | Not met |
| Same, 10 iterations, vector (`simd/archsimd`, AVX2, `GOEXPERIMENT=simd`) | 20 Mbit/s | **18.6 Mbit/s** (median of 8; 16.3-20.5); output identical to scalar | Not met (within 7%) |
| Scalar with early stopping (at most 25, DESIGN.md section 8), Eb/N0 3.0 dB | 20 Mbit/s | 19.4 Mbit/s (mean 3.5 iterations) | Not met |
| Scalar, 10 iterations, 4 / 8 / 16 goroutines | | 30.7 / 43.7 / 49.7 Mbit/s aggregate | |

**S3 is not met.** The otherwise branch, "reduce iterations or use word-parallel arithmetic", was
taken and is recorded here; neither reaches 20 Mbit/s per core at a fixed 10 iterations. The portable
decoder would need about 4 iterations. The vector decoder reaches 93% of the threshold at 10 iterations
(it would pass at about 9, estimated from the scalar scaling, not measured), but it needs a Go
experiment and is not allowed in release builds (DESIGN.md section 8). With early stopping, as DESIGN.md
specifies the decoder, the portable decoder gives 19.4 Mbit/s at Eb/N0 3.0 dB, which also falls short
of 20; the 3.0 dB point was this spike's choice, 0.5 dB above the waterfall, and at 2.5 dB the figure is
13.4 Mbit/s. The vector decoder with early stopping was not measured.

The matrices: obtained from two independent published implementations, which agree entry for entry
for all four rates, with two further cross-checks (section 2).

## 2. The matrices

`internal/fec/ldpc/ieee80211n_1944.txt` holds the IEEE 802.11n (802.11-2020 Annex F) base matrices for
n = 1944, Z = 81: 12, 8, 6 and 4 rows of 24 shifts for rates 1/2, 2/3, 3/4 and 5/6 (24 x (1 - R) rows,
not 12 for every rate). `-1` is an all-zero block. Its SHA-256 is
`c51a02dd2b4916fb182df0e7d02d9d5824eb6b6c0f6dd7a6895a220cc7a3514e`.

Each source was downloaded as a tarball of the named commit into its own empty directory and parsed
as data by a throwaway Go program (none of their code was run). The data file carries the same
attribution in its header. The 802.11 standard itself was not consulted.

The parser (`internal/fec/ldpc/matrices.go`, `ParseBaseMatrices` and `Base1944`) was written tests
first; its tests check dimensions, shift range, the dual-diagonal parity structure (first parity
column with shifts 1, 0, 1; then a dual diagonal of unshifted identities), spot values, the SHA-256
of the embedded file, copy semantics and every parse error. Coverage 98.5%.

## 3. Method

Code: `spikes/s3` (in the root module; no new dependencies).

- **Code.** `normal`: rate 3/4 mother code, k = 1,458; 1,056 information bits, 402 known-zero bits,
  486 parity bits; 1,542 sent bits (FORMAT.md section 8).
- **Encoder.** Systematic, through the dual-diagonal structure: q0 is the sum of the per-row
  information syndromes, then q(i+1) follows row i. Every codeword of 20 random words per rate
  (unshortened, all four rates) and of the shortened code satisfies H c = 0, checked by a separate
  sparse multiplication; a flipped bit is detected.
- **Decoder.** Layered (one layer per block row), normalised min-sum with factor 0.75 computed as
  `m - ceil(m/4)` (= floor(3m/4)), int16 posteriors clamped to +-16383, int16 messages, input LLRs
  int8. Each layer is processed block-wise: for each of its blocks the 81 rotated posteriors are read
  as two contiguous runs, so there is no per-bit modulo. Block columns that are entirely shortened
  (4 of the 5 shortened blocks) are left out: a known-zero variable never changes a check's sign and
  is never its minimum. That leaves 5,913 edges per iteration of the 6,885 in H. The minimum search is
  branch-free (1.5x faster than with branches on noisy input).
- **Vector decoder** (`ldpc_simd.go`, build tag `goexperiment.simd && amd64`): the same algorithm with
  `simd/archsimd.Int16x16`, 16 checks at a time (81 padded to 96); rotated blocks are loaded directly
  from the posterior array except for the one 16-lane chunk that wraps. Its hard decisions and
  posteriors equal the scalar decoder's, bit for bit, on every one of 1,500 frames at 2.25 dB.
- **Channel.** BPSK over AWGN at Eb/N0 relative to the net rate 1056/1542; LLR = 2y/sigma^2, scaled by
  4 and clamped to int8. The benchmark cycles 64 noisy codewords at Eb/N0 = 2.5 dB (in the
  waterfall), decoding each with exactly 10 iterations and no early stop. Throughput = decoded
  codewords x 1,542 / time.

## 4. Results

Throughput, one goroutine (`-cpu 1`), Mbit/s of sent bits:

| Decoder | Iterations | Runs | Median | Range |
| --- | --- | --- | --- | --- |
| Scalar | 10 | 8 | 7.6 | 7.4-8.3 |
| Scalar | 8 | 5 | 10.4 | 10.0-10.7 |
| Scalar | 6 | 5 | 13.5 | 12.1-13.8 |
| Vector (AVX2) | 10 | 8 | 18.6 | 16.3-20.5 |
| Scalar, early stop, max 25, 2.5 dB | mean 5.5 | 5 | 13.4 | 12.9-13.6 |
| Scalar, early stop, max 25, 3.0 dB | mean 3.5 | 5 | 19.4 | 16.8-21.1 |

The machine is the one of S1.md section 2 (Core Ultra 9 285H under WSL2); single-thread figures vary by
about +-10% because WSL2 moves vCPUs between performance and efficient cores.

Frame error rate (300 frames per point, scalar decoder):

| Eb/N0 (dB) | 1.5 | 2.0 | 2.25 | 2.5 | 2.75 | 3.0 |
| --- | --- | --- | --- | --- | --- | --- |
| 10 iterations | 0.95 | 0.47 | 0.14 | 0.017 | 0 | 0 |
| 25 iterations | 0.91 | 0.29 | 0.05 | 0.010 | 0 | 0 |

Early stop, at most 25 iterations: mean 8.4 iterations at 2.25 dB (FER 23/300), 5.5 at 2.5 (2/300),
3.5 at 3.0, 2.7 at 3.5, 2.2 at 4.0 (0/300 each). This is a sanity check only (a waterfall near
2-2.5 dB for a rate-0.68 code of this length is plausible); the published-threshold test of DESIGN.md
section 8 is still to be written in M1.

The 0.75 factor's rounding matters: computing it as `m/2 + m/4` (each rounded down) raised the frame
errors at 2.25 dB from 239 to 266 per 1,500 frames.

## 5. Document changes (applied in phase 2)

The orchestrator did not accept a redefinition of the threshold; the numbers stand as measured.
DESIGN.md section 8 now records them, describes the decoder as built here (floor(3m/4), shortened
block columns left out of the schedule), and states that release builds must not depend on a Go
experiment or an amd64-only package: the portable decoder is the default on all six targets, and a SIMD
path may exist only as an optional build behind a tag, tested for identical output (as
`TestSimdMatchesScalar` does here: identical decisions and posteriors on 1,500 frames).

The brief's "12 x 24 entries per rate for 1944" is true only for rate 1/2; the data file has
24 x (1 - R) rows per rate (12, 8, 6, 4). No document contains the error.

## 7. Reproduce

From the repository root:

```sh
go test -cover ./internal/fec/ldpc/
go test -v ./spikes/s3/                                    # H c = 0, noiseless decode, FER tables
go test -run '^$' -bench 'Decode' -cpu 1 -count 5 ./spikes/s3/
go test -run '^$' -bench 'DecodeParallel' -cpu 4,8,16 ./spikes/s3/
GOEXPERIMENT=simd go test -v -run Simd ./spikes/s3/        # vector decoder equals scalar
GOEXPERIMENT=simd go test -run '^$' -bench 'SimdDecode' -cpu 1 -count 5 ./spikes/s3/
```

The comparison of the sources was a throwaway program (not committed): it extracted each source's
integers with regular expressions (for source 4, by replaying its `set_col` / `set` calls and its
dual-diagonal loop) and compared them with source 1 entry by entry.
